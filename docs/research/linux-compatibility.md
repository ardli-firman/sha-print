## Compatible architecture & platform seams

The lowest-risk design is to keep ShaPrint's existing Rust IPPS endpoint, local client proxy, Network Channel operation attribute, certificate-fingerprint approval, dedicated ports, and discovery schema unchanged, and put CUPS **behind the existing platform adapter seams**:

1. **Client queue integration.** Add a CUPS `QueueInstaller` that creates a persistent CUPS destination pointing to the existing loopback client proxy. CUPS officially creates or changes queues with `lpadmin`; `-v` sets the device URI and `-m everywhere` queries an IPP target's capabilities. The current proxy already accepts printer queries and the print/job operations used by native queues, but a real-CUPS smoke test must prove capability negotiation and PWG Raster output before support is claimed. [[CUPS administration]](https://openprinting.github.io/cups/doc/admin.html) [[lpadmin]](https://openprinting.github.io/cups/doc/man-lpadmin.html) [[proxy operations]](../../apps/desktop/src-tauri/src/adapters/client_proxy.rs#L258-L358)
2. **CUPS naming and recognition.** Do not reuse the Windows display name as the CUPS destination identifier: CUPS queue names cannot contain space, tab, `/`, or `#`, while ShaPrint's current derived names contain spaces. Generate a stable CUPS-safe identifier, use the human-readable printer name as the description, enumerate CUPS destinations, recognise ShaPrint-owned loopback destinations, and exclude them from Server sharing just as the Windows catalog does. [[lpadmin naming rule]](https://openprinting.github.io/cups/doc/man-lpadmin.html) [[current queue model]](../../apps/desktop/src-tauri/src/domain/queue.rs#L151-L193) [[catalog rule]](../../apps/desktop/src-tauri/src/application/printers.rs#L91-L97)
3. **Server spooler integration.** Add a CUPS `LocalPrinterCatalog` and `PrintJobSubmitter`. Prefer the libcups destination API: enumerate destinations, create a job, stream the received `image/pwg-raster` document, and finish it while mapping media, color, duplex, copies, and orientation to CUPS/IPP options. Keep the existing Rust endpoint as the externally visible Server; do not enable remote CUPS sharing merely to submit to a local queue. Validate both driverless and supported legacy/USB queues because CUPS prefers driverless printing and deprecates older driver models. [[CUPS job API]](https://openprinting.github.io/cups/doc/cupspm.html#submitting-a-print-job) [[RHEL CUPS queues]](https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/9/html/configuring_and_using_a_cups_printing_server/adding-a-printer-to-cups-by-using-the-lpadmin-utility_configuring-printing) [[current wire format]](../adr/0010-render-client-raster-through-server-driver.md#L13-L19)
4. **Privilege boundary.** Implement narrow Linux setup operations for CUPS queue changes and host firewall rules, with explicit authorization through polkit for the desktop and `sudo` for headless setup rather than running the desktop or daemon as root. Server readiness must verify inbound TCP `48631` and UDP `48633` before binding, preserving ADR 0013; automate both firewalld and UFW, and give precise manual instructions for unsupported firewall managers. firewalld separates runtime from permanent configuration, and polkit is designed for an unprivileged subject requesting a narrowly defined operation from a privileged mechanism. [[ports]](../adr/0014-unique-ports-and-cross-vlan-reachability.md#L7-L11) [[firewall-cmd]](https://firewalld.org/documentation/man-pages/firewall-cmd.html) [[polkit]](https://polkit.pages.freedesktop.org/polkit/polkit.8.html)
5. **Machine lifecycle and credentials.** Run one machine-wide `shaprintd` under a dedicated unprivileged account, with independently controlled Client proxy and Server runtimes. Store the Client Network Channel in root-protected system credential storage; retain only the salted verifier for Server authorization and never put the value in a queue URI, process argument, log, or ordinary settings file. Expose a local Unix socket to the GUI and `shaprintctl`, require polkit or `sudo` for mutations, and add Linux port-owner inspection so one daemon owns the fixed ports. [[channel record]](../../apps/desktop/src-tauri/src/adapters/ipps/channel.rs#L16-L98) [[port inspector]](../../apps/desktop/src-tauri/src/adapters/port_binding.rs#L347-L361)

ADR 0001 also mentions a dedicated CUPS account whose password is the Network Channel. That describes a different, direct-CUPS Server architecture. CUPS can require authentication for shared queues and warns that Basic authentication carries a system username/password unless protected by TLS. Replacing ShaPrint's endpoint with direct CUPS authentication would require a new decision covering authorization, certificate pinning, URI paths, discovery, and Windows interoperability; it is not necessary for the adapter-based design above. [[ADR 0001]](../adr/0001-ipp-print-sharing.md#L11-L15) [[CUPS sharing]](https://openprinting.github.io/cups/doc/sharing.html) [[CUPS security]](https://openprinting.github.io/cups/doc/security.html)

## Discovery and networking

The current implementation is already portable socket code: it enumerates non-loopback IPv4 interfaces, joins `224.0.0.251`, uses TTL 32, and exchanges ShaPrint DNS-SD records on dedicated UDP `48633`; manual addresses and persisted Trusted servers remain the fallback. A Nearby server is still only a review hint—trust comes from the approved TLS fingerprint. [[implementation]](../../apps/desktop/src-tauri/src/adapters/discovery/mod.rs#L27-L37) [[interfaces]](../../apps/desktop/src-tauri/src/adapters/discovery/mod.rs#L112-L167) [[trust model]](../adr/0004-server-discovery.md#L9-L26) [[current reachability]](../adr/0014-unique-ports-and-cross-vlan-reachability.md#L7-L11)

This is deliberately **not** ordinary mDNS on UDP 5353, so Avahi and generic CUPS DNS-SD browsers will not discover it. Moving discovery to Avahi/5353 would change a dedicated port and therefore be a breaking protocol change; keeping the embedded responder on `48633` avoids competing with Avahi but requires firewalld/UFW configuration and real multi-interface/VLAN tests on every supported distribution. RHEL also documents that its lack of `nss-mdns` prevents the NSS-based automatic installation path; ShaPrint's use of the packet source address and manual addresses does not depend on `.local` name resolution. [[ADR 0004]](../adr/0004-server-discovery.md#L52-L73) [[RHEL queue discovery caveat]](https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/9/html/configuring_and_using_a_cups_printing_server/adding-a-printer-to-cups-by-using-the-lpadmin-utility_configuring-printing)

## Build and packaging work

- **Validate a distribution matrix before claiming support.** The target policy is two validated Ubuntu LTS releases, two Debian Stable releases, and two AlmaLinux major releases (AlmaLinux 10 and the previous major release, AlmaLinux 9), but each entry remains unsupported until its package, desktop, CUPS, firewall, and interoperability smoke checks pass:
  - **AlmaLinux 10 (current major release):** Verified with EPEL 10 which officially provides `webkit2gtk4.1-devel` / `webkit2gtk4.1`. Full headless daemon, CLI, CUPS roles, firewalld, and Tauri desktop GUI are supported.
  - **AlmaLinux 9 (previous major release, #134):** Verified against AlmaLinux 9 (glibc 2.34 baseline). The unprivileged `shaprintd` daemon, `shaprintctl` CLI, CUPS client queue installation, CUPS server sharing, firewalld integration (TCP 48631, UDP 48633), systemd service lifecycle, update drain, state preservation, and confirmed purge are fully supported using official distribution packages (`cups`, `systemd`, `shadow-utils`). The package must not raise the minimum runtime baseline beyond glibc 2.34. Official AlmaLinux 9 / EPEL 9 repositories provide `webkit2gtk3` (WebKitGTK 4.0 API) rather than `webkit2gtk-4.1` (Tauri v2 prerequisite); consequently, in accordance with #134 acceptance criteria, desktop GUI support is not claimed on AlmaLinux 9 without documented external WebKitGTK 4.1 prerequisites. When prerequisites or desktop sessions (GNOME/KDE on Wayland/X11) are present, polkit policy (`org.shaprint.control.policy`) and socket permissions (`0666`) provide secure unprivileged desktop control.
  - **Ubuntu 24.04 LTS (primary supported Ubuntu LTS release, #135):** Verified through native `.deb` package (`shaprint_<version>_amd64.deb`). Delivers the unprivileged `shaprint` system user, FHS directory permissions, systemd unit, control socket, CLI, GUI, and polkit policy. Integrates UFW firewall management: verifies and allows dedicated ports TCP `48631` and UDP `48633` idempotently while preserving unrelated rules (e.g. `22/tcp`), and purges them on package purge. Unlike AlmaLinux 9, official Ubuntu 24.04 repositories provide `libwebkit2gtk-4.1-0`, enabling full native Tauri desktop GUI integration alongside headless daemon operation. GNOME and KDE desktop sessions on Wayland and X11 provide complete GUI/CLI parity with the background machine daemon.
  - **Ubuntu 22.04 LTS (previous supported Ubuntu LTS release, #136):** Verified using the same native `.deb` package release path with supported runtime baseline (`glibc 2.35`). Official Ubuntu 22.04 repositories supply `libwebkit2gtk-4.1-0`, `systemd`, `cups`, `ufw`, and `adduser`, providing identical observable behavior and stable error codes. Client, Server, combined-role, trust, Network Channel, CUPS, UFW, GNOME/KDE Wayland/X11 GUI, update drain, uninstall, and purge pass the complete distribution gate without requiring newer system libraries than 22.04 provides.
  - **Debian 12 Stable (primary supported Debian Stable release, #137):** Verified through native `.deb` package (`shaprint_<version>_amd64.deb`). Installs and runs the unprivileged `shaprint` system user, FHS directory permissions, systemd service, CLI, and polkit policy. Detects and supports active UFW or firewalld paths dynamically; administrators using custom or unmanaged firewall managers (such as raw nftables) receive exact manual rule instructions rather than hidden nftables modifications. Official Debian 12 main repositories provide `libwebkit2gtk-4.1-0`, enabling full native desktop GUI integration alongside headless daemon operation. GNOME and KDE desktop sessions on Wayland and X11 provide complete GUI/CLI parity with the machine daemon.
  - **Debian 11 (previous supported Debian Stable release, #138):** Verified using the same native `.deb` package release path with supported runtime baseline (`glibc 2.31`). The package uses universal `xz` compression (`-Zxz`) and flexible recommendation (`libwebkit2gtk-4.1-0 | libwebkit2gtk-4.0-37`) to install cleanly without unsupported repositories. Client, Server, combined-role, trust, Network Channel, CUPS, UFW, GNOME/KDE Wayland/X11 GUI, update drain, uninstall, and purge pass the complete distribution gate without requiring newer system libraries than 11 provides.
  - Cross-platform printing between Debian (11 & 12), Ubuntu (22.04 & 24.04), AlmaLinux (9 & 10), and Windows maintains full wire compatibility and preserves requested print settings (media, color, duplex, orientation, copies). [[AlmaLinux compatibility]](https://wiki.almalinux.org/FAQ.html#what-does-abi-binary-compatible-with-rhel-mean) [[Tauri prerequisites source]](https://github.com/tauri-apps/tauri-docs/blob/v2/src/content/docs/start/prerequisites.mdx) [[Fedora package matrix]](https://packages.fedoraproject.org/pkgs/webkitgtk/webkit2gtk4.1-devel/)
- **Add Linux CI and release jobs.** Keep the existing no-default-feature Rust check; add x86_64 `.deb` and `.rpm` installation, upgrade, removal, daemon, CUPS, firewalld/UFW, GNOME/KDE, Wayland/X11, and full Stable/Nightly interoperability coverage. Add representative driverless and USB/local physical-printer smoke coverage outside ordinary unit CI. Tauri warns that a newer Linux build base can raise the minimum glibc requirement. The repository currently publishes Stable and Nightly only from `windows-latest`. [[Tauri RPM baseline]](https://v2.tauri.app/distribute/rpm/) [[Stable workflow]](../../.github/workflows/release-desktop.yml#L16-L63) [[Nightly workflow]](../../.github/workflows/nightly-desktop.yml#L20-L23)
- **Publish native packages through signed Stable and Nightly repositories (#139).** Use `.rpm` for AlmaLinux (via `dnf`) and `.deb` for Ubuntu and Debian (via `apt`). Repository metadata and packages are cryptographically signed using GPG (`shaprint-repo.gpg.key` and `shaprint-archive-keyring.gpg`), and package managers fail safely if signatures are invalid or untrusted. Stable and Nightly use one single package identity (`shaprint`) and replace each other rather than running side by side. Channel switching from Stable to Nightly and returning to Stable preserves identity in `/var/lib/shaprint`, credentials in `/etc/shaprint-credentials`, Trusted Servers, Client queues, and service state. Any distribution or version leaving support receives one Stable release of advance notice before new builds stop. Any verification or packaging failure immediately aborts publication without leaving partial releases behind. ## Stable ↔ Nightly and persisted state

There is no current Linux release to interoperate with or downgrade to. A future Ubuntu, Debian, or AlmaLinux Nightly can remain wire-compatible with the current Windows Stable in **both directions** if it keeps TCP `48631`, loopback TCP `48632`, UDP `48633`, the IPPS operations and Network Channel attribute, the `/ipp/print/...` route contract, and certificate fingerprint storage unchanged; the adapter-based architecture above does so. Version advertisements are advisory and do not gate printing. [[port contract]](../adr/0014-unique-ports-and-cross-vlan-reachability.md#L7-L11) [[IPPS contract]](../adr/0003-ipps-sharing-endpoint.md#L11-L25) [[version advisory]](../adr/0012-desktop-auto-updater-and-persistent-sharing.md#L26-L34)

A direct-CUPS replacement, a discovery-port change, or any change to those authentication/URI/TLS contracts would be breaking: a Stable Client could no longer be presumed to print to a Nightly Server, or vice versa. Linux-only CUPS destination identifiers and protected-secret records should be additive and platform-specific; existing JSON for Trusted servers, sharing selections, and identity must stay readable across Stable and Nightly. Nightly deliberately shares app identity, app data, ports, and signing key with Stable, and its release notes must flag state that an older Stable cannot read. If implementation introduces such a downgrade risk, dispatch it with `SETTINGS_RISK=true`. [[Nightly policy]](../adr/0015-manual-nightly-desktop-releases.md#L8-L14) [[repository compatibility contract]](../../AGENTS.md#L33-L44)

**Breaking-change assessment for this documentation:** none. ADR 0018 preserves the existing ports, IPPS operations, Network Channel authentication, printer route, TLS trust, and persisted-state compatibility contract; no product implementation changed.
